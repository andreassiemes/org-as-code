# OKF Export Example — Steering Committee

This directory is **example output**: a conformant [OKF v0.1](https://github.com/GoogleCloudPlatform/knowledge-catalog) bundle
generated by `orgspec export --target okf` from `source/opi.yaml` (an OPI v0.6 document —
the Steering Committee example from `examples/governance/steering-committee.yaml`, upgraded to the v0.6 shape).

The bundle exercises the **complete OPI→OKF type vocabulary** (spec §1.1):
`Organization` (`org.md`), `Org Unit`, `Role`, `Committee`, `Decision`, `Agent`, `Drift`,
plus two `knowledge[]` concepts (`Playbook`, `Reference`). It follows the same export pattern
as the minimal worked example in `spec/opi-v0.6.md` §12.

The OPI source remains the single source of truth (Design Decision D9); this bundle is a
regenerable, portable projection — readable by any OKF reader with no OPI-specific tooling.

Conformance (OKF v0.1 §9):

* Every non-reserved `.md` carries parseable YAML frontmatter with a non-empty `type` (Rule 73).
* Reserved files follow OKF structure: sectioned bullet-list `index.md` files (frontmatter only at the
  bundle root, declaring `okf_version: "0.1"`), `log.md` with ISO 8601 `## YYYY-MM-DD` headings, newest first (Rule 74).
* All cross-links are absolute bundle-relative (`/…`) and resolve inside the bundle (Rule 75).
* OPI fields not covered by OKF's recommended fields travel as `x-opi-*` extension keys, making the
  bundle losslessly re-importable via `orgspec import --okf` (§3).

Note: `source/opi.yaml` is *not* part of the OKF bundle (it is the input); OKF only constrains `.md` files.
This README itself carries `type` frontmatter because OKF v0.1 reserves **only** `index.md` and `log.md` —
any other `.md` inside a bundle (including a README) is a concept document and MUST have frontmatter with
a non-empty `type` (OKF §9), otherwise the whole bundle is non-conformant.
